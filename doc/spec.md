# 马赛克拼图（Mosaic Assemble）— 游戏设计规格

## 概述

这是一个新一代类扫雷游戏。相比传统扫雷，核心创新在于引入了"区域"概念——棋盘被划分为多个不规则区域，玩家需要通过推理逐区域完成标记。

## 核心玩法

### 区域机制

- 整局游戏棋盘被分为多个区域，每个区域包含多个格子。
- 玩家可以同时在一个或多个区域内进行标记操作。
- 当某个区域内的所有格子都被正确标记时，该区域完成。
- 当所有区域完成时，本局游戏结束。
- 区域边界不是标准直线，采用不规则形状。初始实现使用算法生成的马赛克化边界，后续可扩展多种风格：
  - Voronoi 图风格
  - 自然曲线风格
  - 真实照片马赛克化 + 抠图算法生成（远期目标）

### 格子类型与数字

- 每个格子有 **a** 和 **b** 两种类型（由生成算法随机分配）。
- 每个格子上显示一个数字，表示该格子的**九宫格范围内且属于同一区域**的 **a 类型**格子的数量。
- 数字范围：0 ≤ n ≤ m，其中 m 是该格子在区域内九宫格邻居数 + 自己（2 ≤ m ≤ 9，边界格子 m 较小）。
- 数字**并非全部初始可见**，可见比例支持配置（类似传统扫雷的"翻开"体验）。

### 玩家操作

- **左键**：向 a 方向切换标记
- **右键**：向 b 方向切换标记
- 三态切换逻辑（`未标记 ↔ a ↔ b`）：

| 当前状态 | 左键操作 | 右键操作 |
|---------|---------|---------|
| 未标记   | 变为 a   | 变为 b   |
| 标记为 a | 变为未标记 | 变为 b   |
| 标记为 b | 变为 a   | 变为未标记 |

- 支持按住鼠标拖拽进行连续标记。

### 超标判定

假设某个格子的数字为 n，其在区域内九宫格邻居 + 自己共 m 个格子：

- 当区域内九宫格中**标记为 a 的数量 > n** 时，该格子**超标**。
- 当区域内九宫格中**标记为 b 的数量 > (m - n)** 时，该格子**超标**。

超标时，该格子的数字变为红色，格子底色和其它样式不变。玩家不会直接被告知哪一步标记出错了，但错误标记最终必然导致区域内出现超标，玩家需要据此回溯推理。

### 可解性

当前阶段暂不强制保证可解性（即不需要猜测就能推理出全部答案）。先构建基础能力，算法层面后续再完善。

## 棋盘参数（初始值，后续可调整）

| 参数 | 默认值 |
|------|-------|
| 棋盘大小 | 100 × 100 |
| 区域数量 | 6 |
| 初始数字可见比例 | 待定（可配置） |

每次生成新棋盘时，区域布局、a/b 类型分布均须随机。

## 视觉设计

- 网格线可见，**区域边界线条更粗**以突出区域划分。
- 格子三种状态（未标记 / 标记为 a / 标记为 b）使用不同颜色区分，但须保持**同色系低反差**，整体棋盘视觉不花哨。
- 超标时**仅数字变红**，格子底色保持不变。
- 整体深色主题，冷色调为主，珊瑚/橙色作为强调色。

## 音效

- 标记为 a 和标记为 b 须有**不同的音效**，确保玩家可区分。
- 由于用户可能按住鼠标拖拽连续标记，音效须满足：
  - 短促（attack 快、decay 短，类似 percussion 短音）
  - 高频不宜过多，避免快速连续播放时刺耳
  - 支持快速连续触发不重叠冲突

## 交互面板

当前阶段暂不做侧边交互面板。后续可加入区域进度信息（如当前区域已标记格子 / 总格子数）。
